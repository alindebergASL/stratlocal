# Useful brief → confirmed follow-up

Status: implementation and verification in progress; not a release receipt.

## Scope

Improve the existing meeting brief and action handoff, not add a new dashboard. The top view contains purpose, at most three cited facts, an explicitly unestablished hypothesis, at most three questions, the supported deal/play connection or an explicit gap, one proposed next step, and an uncertainty note. Existing saved briefs are projected without rewriting or regenerating them; their complete sections remain in the details disclosure. No paid research call is needed to read a brief or confirm a follow-up.

The follow-up handoff requires a person to review/edit the action and explicitly choose an owner/date or mark either undecided. It preserves AI origin and meeting/evidence references. Merely opening it writes nothing. A repeat for the same meeting and stored brief version cannot create another action. Missing support is a refusal, not permission to silently drop a citation. Unknown mutation outcomes retain input and lock writes until authenticated read-only reconciliation.

## Verification contract

- New and legacy brief schemas/rendering; no invented content for absent legacy fields; full details preserved.
- Typed/account-scoped citations; exact finding navigation and evidence dates. A retained finding omitted from a bounded prompt or deduplicated there must still resolve for a saved brief. Archived/retracted/wrong-account references remain visibly unavailable.
- Explicit owner/date choices; AI origin and evidence persisted; opening a handoff makes no mutation or AI call.
- Transactional same-brief replay protection, including changed wording/owner/date and an archived original action. Old brief versions are distinguished from current ones.
- Browser replay of response loss after a real commit, retained fields, locked resubmission, malformed recheck remaining locked, and GET-only read-back showing persisted values without a duplicate.
- Authentication and missing/archived target handling on the read-back endpoint.
- Full existing suite and browser flows, independent technical review, exact-head CI, unchanged database schema, exact-image backup/restore rehearsal, preservation gate and live checks before release is declared complete.

All committed fixtures and captures used for product evaluation are synthetic. `AI_FAKE` browser scenarios test the actual application pipeline against deterministic replay responses; they do not validate live model output quality. Production briefs will not be automatically regenerated by this release. Collaboration freshness is the separately approved next slice, not part of this one.
